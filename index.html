Currency & Exchange Rates
Foreign fees are converted to ₹ on the revenue dashboard so India and International can be compared. Live rates are used for the current month; each completed month keeps the rate it was frozen at, so past figures don't move.
Manual values are the fallback whenever a live fetch fails or is turned off. Enter how many rupees one unit is worth.
Frozen Monthly Rates
A completed month is frozen at the rate in force when you freeze it. Totals keep recalculating from live payment data, so a late payment still counts — only the conversion rate is fixed.
Fee Bands by Level
What a student at each level should be paying, in each currency. The Payments screen scores every student against the band for their current level and flags anyone priced below it — which is how a student halfway through Level 2 still on the Level 1 rate shows up. Leave a cell blank if you have no band for it; those students read “No band” rather than being scored against nothing.
Repair · Level Progress
How far each student is through their current level, used on the Payments screen to flag who is close to a fee change. It is kept up to date automatically whenever a topic is marked or a profile is opened — at no extra reading cost, because that data is already loaded at those moments. This seeds it for students nobody has opened yet. Run it once; after that it looks after itself. It reads every student's progress, so it is the one expensive button here — there is no need to run it repeatedly.
Repair · Fee History
Each student's fee now carries the month it took effect, so raising a fee leaves earlier months at the rate they were actually billed. Students who have never had a fee change carry no history yet, which would leave every past month with no rate at all. This writes one entry per student — their current fee, effective from the month they joined. Run this once before changing any fees.
Repair · Parent Sign-in
A parent signs in with Google and the app finds their children by matching their address against the student's parentEmails list. That list is built from the Parent / Student Email field, but only when a student is saved through the Add / Edit form — records that came in any other way carry the email without the list, and those parents are told their account isn't linked to any student. This rebuilds the list for every student from the email already on their record. Nothing else on the record is touched.
Repair · Payment Currency
Payments are always received in rupees. Rows imported before this was settled may be tagged with the student's quoted currency (CHF, USD, CAD…), which made them convert and inflated revenue. This re-tags every such row as ₹ without touching the amounts.
Data Start
Nothing was recorded before this month, so attendance, assignments and payments are never shown earlier. Move it back if you ever backfill older history.
Student Detail · History From
Attendance and assignments began being tracked on different dates. These floors apply to the cards and month drill-downs on a student's page only — the trends and tutor screens keep using Data Start above, so the same student can read differently in the two places. Leave a row at the Data Start month to keep today's behaviour.
● Unsaved changes Saves currency rates, data start and history months. The repair tools and frozen rates have their own buttons.
